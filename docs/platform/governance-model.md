# Governance model

How shipfoundry stays consistent as it grows. This doc explains **why** each invariant exists; [`lint-platform.sh`](../../lint-platform.sh) **enforces** them. When the two disagree, the script wins — change the script first, then update this doc.

> Single source of truth: process *rules* live in [CLAUDE.md](../../CLAUDE.md); cross-skill *incidents/lessons* live in [lessons.md](../../lessons.md). This doc does not restate them — it maps each rule to its executable check.

## The core principle

Recurring platform incidents almost always have the same shape: **an invariant enforced by a human remembering to run a grep.** Memory does not scale to hundreds of skills or multiple maintainers. So the governance model is: *invariants are executable, not remembered.*

`./lint-platform.sh` is the close-out checklist. Run it before declaring any skill edit complete. It exits non-zero on any FAIL.

## The invariants (what the lint enforces)

| # | Check | Level | Why it exists |
|---|---|---|---|
| 1 | Source ↔ dist parity (every skill has a matching-version zip; no orphans) | FAIL | A version bump with no rebuild ships stale behaviour; an unversioned zip breaks the name-match invariant |
| 2 | No internal-only paths in dist zips (`*-internal.md` files, `_internal` paths) | FAIL | Confidential content must never leave the repo in a shareable bundle |
| 3 | No `[`/`]` in dist filenames | FAIL | The claude.ai uploader rejects bracketed paths |
| 4 | Description ≤ 1024 chars | FAIL | The claude.ai uploader rejects longer |
| 5 | No angle-bracket tags in description | FAIL | `<Product>` parses as XML; upload rejected — use `{braces}` |
| 6 | Body ≤ 500 lines (warn > 450) | FAIL / WARN | SKILL.md loads into context on every trigger; every line competes |
| 7 | Dist manifest in sync (`dist/MANIFEST.json` sha256 matches each zip) | FAIL | The manifest is the integrity record of what should be uploaded to the org; a stale one means a zip was rebuilt outside `build-dist.sh` |
| 8 | Internal content is covered by a `.distignore` | FAIL | Documented-intent half of leak prevention (check 2 is the runtime half) |
| 9 | Trigger-phrase collisions across descriptions | WARN | Two skills sharing a trigger phrase can mis-route at a dispatcher; grows with scale |
| 10 | Frontmatter parses as strict YAML (real parser, not awk) | FAIL | The claude.ai org Skills uploader uses a strict YAML parser; an unquoted scalar containing `": "` (colon-space) parses as a nested mapping and the upload is rejected. The awk-based helpers don't catch it. Needs python3+PyYAML (CI installs `python3-yaml`); WARNs if unavailable |
| 11 | Local symlink install coverage — every source skill has a resolving `~/.claude/skills/` symlink | WARN (local-only) | The personal Claude Code install discovers skills via `~/.claude/skills/` symlinks into the repo; a skill that never gets its link is invisible to the local `/` menu. `new-skill.sh` creates the link — this is the safety net. **Self-skips** when `~/.claude/skills` is absent (CI / fresh checkout) or doesn't manage this repo, so it never breaks the pipeline |
| 12 | CLAUDE.md skill inventory parity — every skill is named in CLAUDE.md; no stale `skills/<name>` reference | FAIL | The maintenance step "update CLAUDE.md skill counts + structure tree" was enforced by memory (every playbook says it; no command checked it). This makes it executable — the meta-principle applied to the platform's own highest-traffic drift surface. Forward catches add-without-update; reverse (platform-wide) catches a stale reference to a deleted/renamed skill. Also gates **count claims** (platform-wide): any "<N> skills" claim on an agency-mentioning line of CLAUDE.md or README.md must equal the actual `jarvis-agency-*` dir count — names were guarded, counts were not, and README shipped "30 skills" after the 31st skill landed (an internal fix record). See `lessons.md` 2026-06-26 |
| 13 | Agency registry parity — every producer skill (`*-build-*`) is named in a workbench internal config; every producer name referenced there resolves | FAIL | A workbench's orchestrator/intake route by reading registries in `reference/_internal/*.md` (the producer-capability registry), **not** by scanning the skills folder — so a producer that exists but is unregistered is loadable yet never routed to, and a registry naming a deleted/renamed producer is a dangling route. This is the one by-hand layer that used to be caught only by the independent review; check 13 makes it a gate. It reads the union of the gitignored internal config and the committed sanitized slice (`config/agency-registry.md`, see the paragraph below), **self-skipping only when neither exists**. Reverse is scoped to `*-build-*` producer tokens so non-skill `jarvis-agency-*` identifiers (paired repo names) don't false-positive; verifier-name staleness stays review-caught. Also gates **label-list parity**: every backticked label in a producer-registry row must appear in the config's 'label values' row — the docs-tier wave shipped a registry row whose label was missing from the authoritative label list, stranding stories at validation. And **tier-row completeness**: the config's 'Work tier' marker row must name all four contract tiers (`docs`/`small`/`feature`/`product`) — the docs tier shipped with the row still listing three, so a `TIER: docs` marker would have failed validation against it (an internal fix record) |
| 14 | Model-tier parity — every `jarvis-agency-*` skill has a row in the orchestrator's `reference/model-tiers.md`; every skill named in the table resolves | FAIL | The orchestrator dispatches every subagent on a model tier sized to the work (judgment/adversarial → strongest, mechanical → cheap, no gate below mid, red-team never below strongest). A skill missing from the table would dispatch on the session model by default — silently the strongest and most expensive, the cost-drift this tiering exists to stop; a row naming a deleted/renamed skill is dead policy. Unlike check 13 this runs on **shipped** files (the table ships in the orchestrator), so it holds in CI and a fork too. It also enforces the **tier floor** — no gate/verifier row on the cheap tier, `redteam-security` always strongest — so a later edit cannot silently weaken a gate. Skips on a single-skill run (parity is cross-skill) and self-skips if the table is absent (non-agency fork) |
| 15 | Operator-guide inventory parity — every `jarvis-agency-*` skill is named in `docs/jarvis-agency-operator-guide.md` | FAIL | The operator guide is the founder-facing roster and the source of its Confluence mirror; check 12 guards CLAUDE.md but the guide had no guard, and the docs-tier wave shipped with the guide claiming updates a failed edit script never landed. Forward-only (a stale extra mention is review-caught). Self-skips when the guide is absent (a non-agency fork) |
| 16 | Eval scenario-id uniqueness — each skill’s `evaluations/baseline-evals.json` has unique scenario `id`s | FAIL | eval-runner iterates by array index, so a duplicate id runs but silently breaks per-scenario traceability (“which scenario is …-012?”) — a real review-caught defect the structural checks missed. Needs python3 (JSON parse); WARNs if unavailable |
| 17 | Verifier-branch parity — every non-baseline code type label has a per-stack branch in all three code verifiers (`review-code`, `run-tests`, `redteam-security`) | FAIL | "Adding a producer is a wave" requires a branch in **all three** code verifiers — a load-bearing step the registry documented but nothing enforced, so a producer could land routable yet reviewed/tested/attacked as the house baseline instead of against its own stack rules. The label set is **derived from the config's 'label values' row** (a new producer's label is required automatically); baseline stacks (`backend`/`api`/`frontend`/`data`) are covered by the verifiers' default checks and exempt, `docs` has its single-gate tier, and artifact labels take the artifact path. Named-anywhere like check 13 (a brittle branch-header parse is avoided). Reads the same union as check 13 (internal config + committed slice) and self-skips only when neither exists. Added when the producer roster expanded — six producers × three verifier branches made the by-memory step unenforceable; the check that built it caught its own first draft passing vacuously (an `IFS` bug), which is why it ships adversarially tested |
| 18 | Version frontmatter is semver — every skill's `version:` is `MAJOR.MINOR.PATCH` | FAIL | `build-dist` names the zip and the manifest entry from `version:`, so an empty or malformed value silently produced a `<skill>-v-public.zip` with a garbage manifest version — and check 1's expected-path computation matched it, so parity passed on a broken artefact (VIBE-003). Validate at the source instead |
| 19 | No scaffold TODO placeholders — no skill `description:` still starts with the scaffolder's `TODO` | WARN (FAIL under `--strict`) | `new-skill.sh` scaffolds a TODO description that passes every structural check, so an unfilled stub could be built and uploaded (VIBE-020). WARN keeps local scaffolding friction-free; `--strict` blocks the merge in CI |
| 20 | Producer skeleton parity — every code producer (`*-build-*`) carries the shared skeleton sections (`What it never does`, `What it receives`, `The build process`, `Stack conventions`, `Restricted write`, `Files in this skill`) | FAIL | The code producers share one structural skeleton, and `build-backend` (the original template) drifted from its own descendants and lost the other-stack exclusion rule (VIBE-010). A skill body **is** the dispatched subagent's behaviour spec, so a producer missing a section is running on a different contract. `build-docs` is exempt (documented single-gate divergence, contract 0.4.22). Platform-wide only |
| 21 | Vault-governance mirror fidelity (`verify-mirror`) — a deployed `{vault}/_governance/SOURCE-OF-TRUTH.md` matches the platform contract template once the per-repo slots are masked; plus a self-check that `law_version` agrees across the template frontmatter, its `generated_note` and the SKILL.md body, and that every `{{SLOT}}` is a known slot | FAIL | The Vault-as-Source-of-Truth law is authored once in `skills/jarvis-vault-governance` and deployed to every work repo as a read-only mirror, so "repos never edit the law" was a promise no command checked — a repo quietly softening a rule in its own mirror (dropping pending-intent-inert, say) is invisible to every other check. A raw diff is the **wrong** test, since a faithful mirror legitimately differs in the slots; both sides are masked (`repo_vault_root`/`jira_project_key`/`quarantine_list`/`updated`, the `generated_note` date, and slot values wherever they appear in the body) and everything surviving the mask must match byte-for-byte. A mirror whose `law_version` is **ahead** of the platform can only be a hand-edit → FAIL; **behind** is stale → WARN, with the text comparison skipped on purpose (the platform keeps no historical templates, so a cross-version diff reports law *changes*, not repo *edits*). Runs in the suite against any mirror in this repo, and standalone for any other repo's mirror via `./lint-platform.sh --verify-mirror <path>`. Self-skips when the governance skill is absent |
| 22 | Jira-as-source-of-truth-for-decisions contradiction — no file in the **operative tree** (every skill body, `reference/**` incl. `_internal/`, `docs/`, `CLAUDE.md`, `README.md`, `config/`) claims Jira is the source of truth **unqualified** or for decisions/intent | FAIL | The vault-governance law (law_version 1.1.0) makes the vault authoritative for INTENT and Jira the ledger for EXECUTION. A 2026-07-20 audit found the agency workbench asserting the opposite in nine places, headed by the foundation contract's invariant #1 — a premise every agency skill inherits, so the contradiction propagated by inheritance rather than by copy. Fixed by edit; this check stops the drift back, per the platform rule that a "remember to also update X" note should be a check instead. **Widened 2026-07-21** after a follow-up audit found 8 of the 12 surviving instances outside the first version's reach — its glob stopped at `reference/*.md` (never descending into `_internal/`, where the operative registry lives) and never saw `docs/`, `CLAUDE.md`, `README.md` or `config/`, and its regex required the literal string "source of truth", so every paraphrase walked past it: "the issue **holds the truth**", "**state lives in Jira**", "all **durable state** in Jira", "**intent in Jira**". Both dimensions are fixed; it stays narrow where narrowness is correct — the same claim **scoped to execution state** is the corrected wording and passes (qualifier on its line or the next), and a claim correctly attributing source-of-truth to the *vault* is not a Jira claim. Three exemptions, all deliberate: changelog blocks (the historical record of what the rule used to say — rewriting history to satisfy a lint is the drift this platform refuses); a claim inside **quotation marks** (a plan or review doc citing the pre-split wording is reporting it, not asserting it); and a file carrying the **historical-record banner** (see below the table). Covered by `tests/cases/sot-contradiction.sh`, which asserts it catches the real pre-fix wording and each paraphrase — not merely that it goes green on clean text |
| 23 | Stated-defaults drift — no file in the operative tree contradicts a cross-cutting default registered in `config/stated-defaults.md` (GA-granularity default, PRFAQ owner, the three review states) | FAIL | The 2026-07-21 audit found the GA default flipped to `epic` in exactly one reference line while the contract body, the internal registry and the operator guide all still said `story`. A default stated in one place and consumed in four is the platform's dominant drift shape; `stated-defaults.md` is the single place a new cross-cutting default is registered, and this check is what makes that statement load-bearing rather than aspirational. Each registered literal is matched with `grep -F -i` (verbatim, case-insensitive) — never as a regex, so a maintainer registering a literal cannot accidentally write a pattern that matches half the repo. Same changelog + historical-banner exemptions as check 22. **Scope note:** narrative planning and review documents under `docs/` (outside `_governance/`) are out of scope on purpose — a fix plan legitimately quotes the value it is replacing in a before/after column, and a default is only *wrong* where an agent would act on it. A registry that parses to **zero** literals is a FAIL, not an empty ruleset (loud-on-nonsense). |
| 24 | Internal-config lane-name uniqueness — no Jira lane name appears twice in the internal config's lane table | FAIL | Two `PM Acceptance` rows with **opposite** rules sat in the same table: the new one was appended without deleting the old, and "latest wins" applies to Jira comments, not config tables. A lane name is a key; a duplicate is always a defect. Self-skips when the internal config is absent (a fork without it), like check 13, and **WARNs** rather than passing silently if a config exists but holds no `\| Artifact \| Location \|` lane table — that is a shape change, not an empty ruleset. |
| 25 | Eval scenario self-containment — no scenario `query` carries an unresolved `[PASTE …]`/`TODO`/`<INSERT` placeholder without a resolving fixture | FAIL | `evaluation-strategy.md` states "a self-contained query is the bar, not a `[PASTE …]` stub" and nothing enforced it; a scenario shipped telling the model to review content that was never supplied, and the runner scored the improvisation. The rule as written is **conditional**, so the check is too: a placeholder paired with a fixture is the documented pattern (62 scenarios do exactly that) and passes; without one it fails, and a `fixture` path that resolves to nothing fails equally — a pointer to nothing is a stub wearing a fixture's name. A bare uppercase `TODO` in prose is *not* treated as a placeholder (eval queries legitimately describe `// TODO: implement` stubs in the code under review). Needs python3; WARNs if unavailable, like check 16. |
| 26 | Gate-name → reference parity — every gate named in the orchestrator's gate list is described in `reference/enforcement-gates.md` | FAIL | The body points readers at that reference for "the mechanism and honesty of each gate"; three gates were added to the list and never to the reference, so three controls had no stated mechanism or enforcement standing. **Honest limit, stated plainly:** this compares *content words*, not exact names, because the reference deliberately re-words a gate's title (`` `STATUS-ACTOR:` on every status move`` vs "Every status move records `` `STATUS-ACTOR:` ``") and an exact-string test would red-gate correct files. It catches a gate whose distinctive words are **largely absent** from the reference; a gate that *is* described but whose description is stale or wrong is **not** catchable here and stays review-caught. A renamed section or a zero-bullet list is a FAIL, not a vacuous pass. |
| 27 | Governance-slot self-consistency — `_governance/` prose agrees with the `jira_project_key` slot | FAIL | A botched slot substitution left `repo-config.md` and `run-counter.md` asserting the repo was `UNSET` and Jira-inert while the slot read a real project key — so the law's every-10-runs drift sweep was off on a repo that has a Jira project. The consequence is behavioural, not cosmetic. Gated in **both** directions (slot SET + inert prose; slot UNSET + live-triggers prose). The law mirror `SOURCE-OF-TRUTH.md` is deliberately not scanned — it legitimately describes both branches, and its fidelity is check 21's job. Self-skips when there is no `_governance/`. |
| 28 | Absolute-refusal clause without a permitting case — a skill BODY stating an absolute refusal ("is a stop", "do not proceed", "refuse to") names a permitting case nearby | WARN (FAIL under `--strict`) | An absolute clause with no permitting case has produced denial-of-service defects across multiple skills: *don't work from a stub* became *don't work*; *don't improvise an environment* became *don't test*; *route a missing PRFAQ back* became *refuse the whole pass* — the front door declining to interrogate a founder's intent, and a verifier failing an artifact for honestly declaring an unknown. All of them passed `lint --strict`. The author writes a prohibition holding the counterexamples in mind; the agent reading it has only the prohibition, and the safe reading is to refuse. Enforces CLAUDE.md best-practice #8. **Honest limit:** a prose heuristic that cannot know intent — it sees whether a permitting clause sits near a refusal, not whether the rule is right. Genuine unconditional prohibitions (the GA ceiling, pending-intent-inert, never-provision) are legitimate and must not be softened to silence it; WARN is the correct weight for a heuristic over prose. |
| 29 | Eval receipt for behaviour-level version bumps — a MINOR/MAJOR bump past the version recorded in `config/eval-receipts.md` | **NOTE only; never gates** | CLAUDE.md says run the behavioural gate when behaviour changed, and nothing enforced it — memory-enforced, the shape this platform condemns everywhere else. It matters: in the 2026-07-21 sweep the behavioural gate found **7 of 7** real defects and the structural gates found **0 of 7**. The gate cannot run in CI (live model calls, real money), so the enforceable proxy is a receipt that a run happened at a stated version; `eval-runner.sh` writes the row itself, and only on a full single-skill run that actually graded a scenario (a rate-limited run grades nothing and writes nothing — a receipt from it would assert an eval that never happened). **A never-evaluated skill is reported as a NOTE, not a WARN:** it is a backlog, not a regression this change introduced, and gating on it would turn `--strict` red on every future PR and train people to ignore the check. **Honest limit:** a receipt proves a run was RECORDED at that version — not that the run was good, that its scenarios were the right ones, or that the skill is correct. The `Failed` column exists so a green receipt cannot be read as a green skill. It is also blind to a behaviour change mis-versioned as a patch, which is why maintenance convention #2 now says a change to what a skill DOES is minor, never patch.  **Why it does not gate (changed 2026-07-21, on its first real firing):** the remedy costs real money and is rate-limited — the check fired on a front-door behaviour change that could not be cleared for three days. Gating merges on it would either stall work or push people to silence it by editing the receipt, which would make the whole trail worthless. Its value is a visible, auditable record of what has NOT been replayed. `./run-pending-evals.sh` is the remedy. |
| 30 | Stall-probe coverage — every skill with evals ships a `-900-` stall probe | **NOTE only; never gates** | CHECK 28 catches the absolute-refusal *shape* statically; this is the behavioural half's coverage record. The stall probe ([`evaluation-strategy.md`](./evaluation-strategy.md)) is two fixed-template scenarios asking *a precondition is absent — do you still do your job?* and *an artifact is honest-but-imperfect — do you still pass it?*. `new-skill.sh` scaffolds one for every new skill, so new skills are correct-by-construction; this reports the 38 that predate the convention. **Deliberately never gates:** warning on a pre-existing backlog would turn `--strict` red on every future PR and train people to ignore the output — the same reasoning CHECK 29 applies to never-evaluated skills. **Honest limit:** it counts a scenario id containing `-900-`. It cannot tell whether the probe is well-written, whether its assertions are right, or whether it was ever RUN (CHECK 29 owns the run record). Presence is not proof. |
| 31 | Project-identity allowlist — every project-shaped token in a tracked file is an allowlist member (`PROJ-nn`, `PROJ-EPn`, `LogBench`, `acme`, `fleet-agent`, display names, fixture ids) | **FAIL** | The decoupling sweep found real project identifiers in five distinct token shapes, each escaping the probe written for the previous one; a sixth (bare backticked designator) and a seventh (quoted mixed-case **display name**, e.g. a two-word product name in ordinary prose case) were found later. The seventh mattered most: shapes (a), (b) and (f) all require an ALL-UPPERCASE token, so a display name was invisible to every one of them and survived a full scrub into the tree, the built zips, and two pushed commits — a Jira project has both a key and a display name, and only the key was modelled. Every blocklist sweep missed the next shape, so this check is POSITIVE: a non-member fails. Opposite polarity to `scan-secrets.sh`'s ORG detector, which fires on a match — this fires on a non-match, and the membership test is deliberately independent so it cannot flag the members it exists to permit. **Honest limit:** shape (b) is narrow on purpose — the broad form measured 676 hits on this tree, dominated by the repo's own vocabulary (`AC`, `GA`, `RC`, `PR`). `lint-platform.sh` is exempt because its own regex literals self-match; `scan-secrets.sh` still scans it. |
| 32 | Stated check-count parity — every stated check count equals the actual number of checks | **FAIL** | Count drift is recurrent: stated counts in separate docs fall out of step with the real number, and each hand-fix seeds the next drift. **Counting rule:** the authoritative count is the SET OF CHECK NUMBERS, not the header count and not the function count — `# CHECK 4 + 5` is one header declaring two checks, implemented by one function, so both naive counts under-report by one. The set must be contiguous 1..N (a gap or duplicate is its own FAIL). Self-inclusive by design. `lint-platform.sh` is exempt: it quotes a past count as evidence of the drift. |
| 33 | Instance state is never tracked — no `**/_internal/` path is tracked by the platform repo | **FAIL** | The Model-A public/private split rests on `.gitignore:14`, and .gitignore is a convention `git add -f` overrides silently. CHECK 31 cannot catch it: 31 scans tracked-file CONTENT for project-shaped tokens, and an instance config of opaque ids may match none of them. This asserts REPO STATE instead — is any `_internal/` path tracked. Only the `**/_internal/` half of the internal convention is asserted; `*-internal.md` files are tracked by design and excluded from dist by CHECK 2/8. |
| 34 | Confidential-doc type in the public tree — no assessment/roadmap/gap filename shape, no run-evidence marker | **FAIL** | Assessments and roadmaps belong in the private docs repo; hand enforcement is what produced every escape. |
| 35 | Private-document titles and strategy language — no private doc named in prose, no forward-looking market statement | **FAIL** | The last two escapes were prose, not tokens: private docs named in changelogs, and the unreleased go-to-market direction stated outright. CHECK 31 hunts tokens and cannot see either. **Honest limit:** the unguarded title pattern matched 174 times on a clean tree (all `In Review`), so it is deliberately narrow. |
| 36 | Source ↔ dist CONTENT parity — every file inside a dist zip matches its source byte-for-byte | **FAIL** | Check 1 compares the filename version and check 7 the manifest sha; neither reads the zip's *contents*, so an edit without a version bump left a stale zip and every gate stayed green. The dangerous direction is a zip still shipping text the source no longer has — the zips are a separate distribution path (the claude.ai Skills panel), so a repo-only scrub never reaches them. Needs `unzip`; WARNs without it |
| 37 | Documented hooks are wired and executable — a doc promising a Stop hook must find one wired in `.claude/settings.json`; a wired hook must resolve to an existing executable | **FAIL** | `CLAUDE.md` promised since the initial public release that a Stop hook auto-runs the gate, while `.claude/settings.json` sat at `{}` — the hook body was stripped by the public-release scrub and the two sentences describing it were not, so the repo documented a control it did not have and no check compared the claim to the file. Worse than a plain gap: the promise made the absence *invisible*, since every session reading CLAUDE.md believed the gate was already running. Both directions fail because both have: an unwired promise, and a wired hook whose script was renamed or lost its `+x` (which disarms it silently while lint stays green). Ships adversarially tested — unwiring the hook reproduces the original failure and names `CLAUDE.md:28` and `:152` by line. **Honest limit:** it resolves `hooks/*.sh` references, not arbitrary shell, so a hook invoking something exotic is out of reach; and it verifies the hook is *wired*, never that it *ran*. Needs `jq`; skips without it |

Checks 13 and 17 read from **two merged sources**: the gitignored internal config (instance-specific — cloud id, account ids, real status/transition ids — never committed) and the committed, sanitized slice at [`config/agency-registry.md`](../../config/agency-registry.md) (VIBE-016). The slice carries only the producer-capability registry rows (type label | producer skill | one-line scope), the 'label values' row, and the 'Work tier' row — no instance configuration of any kind. It exists so both checks run their real verdict in CI and on a fresh clone instead of self-skipping there; a forgotten producer registration now fails a PR even without the maintainer's local internal config present. Keep it in sync by hand when you register a producer (the checks' forward-check catches a producer missing from *either* source, not a slice specifically out of sync with the internal config). Both checks self-skip only when **neither** source exists — a fork with no agency workbench at all.

### The historical-record banner (checks 22 and 23)

The prose-contradiction checks scan documents an agent might act on. Some documents in `docs/` are
deliberately **point-in-time**: a dated review, a superseded model, a record of what the system said
on the day it was assessed. Their old wording is *evidence*, not instruction, and correcting it would
destroy the thing they exist to preserve.

A file whose **first 30 lines** carry either of these markers is skipped whole by checks 22 and 23:

- `Retained as a historical record` — the prose convention already used in `docs/` banners.
- `<!-- lint-exempt: historical-record -->` — the explicit form, for a file with no prose banner.

The banner is not a general escape hatch: it exempts the file from these two prose checks only, and
`tests/cases/sot-contradiction.sh` asserts that the same file **without** the banner still fails. Use
it when the document is a record; fix the wording when the document is an instruction.

WARN-level checks (6 soft cap, 9 trigger collisions, 11 local symlink coverage, 19 scaffold TODO placeholders, plus the shape-change warnings on 23/24) report but don't block, because they're advisory not safety. `--strict` promotes warnings to failures for CI — except check 11, which self-skips in CI (no `~/.claude/skills`). Checks 13 and 17 now run in CI too via the committed slice and can trip `--strict` there like any other FAIL-level check.

The internal-content convention (checks 2 and 8) is generic: a file named `*-internal.md`, or any path segment named `_internal`. It lives **once** in [`lib/internal-convention.sh`](../../lib/internal-convention.sh) (`INTERNAL_RE` + `is_internal_path`), sourced by `lint-platform.sh` (checks 2 + 8) and `build-dist.sh` (defensive build-time exclusion, so a forgotten `.distignore` line still can't leak). Change it there; both consumers pick it up — no hand-syncing. (`new-skill.sh`'s scaffolded `.distignore` lists example internal paths as a default; it is not a second definition.)

## Platform tooling (the gates and builders)

| Script | Role |
|---|---|
| `lint-platform.sh` | The **structural gate** — the 37 checks above. `--strict` (warnings fail), `--versions` (authoritative version table), `<skill>` (single-skill), `--verify-mirror <path>` (one deployed vault-governance mirror, in any repo). |
| `scan-secrets.sh` | The **content gate** — refuses secrets (API keys, tokens, private keys) and PII (emails, IPs) in tracked files. `--staged` (pre-commit), explicit files (tests). Allowlist known-safe values in `.secretignore`. |
| `eval-runner.sh` | The **behavioural gate** — replays each skill's `baseline-evals.json` against the model and scores the assertions. Run outside a Claude session. See [evaluation-strategy.md](./evaluation-strategy.md). |
| `run-evals-lean.sh` | Runs the behavioural gate **lean** on a maintainer machine whose global Claude config would otherwise push every call over budget: stash + probe-gate (health/cost/token ceilings, abort-before-spend) + per-run spend ceiling + restore-on-any-exit. See evaluation-strategy.md "per-call cost floor". |
| `build-dist.sh` | Builds the dist zips reading each `.distignore` as the single exclusion source, and regenerates `dist/MANIFEST.json`. |
| `new-skill.sh` | Scaffolds a new skill correct-by-construction (frontmatter + evals stub + `.distignore`) so it passes the lint by default. |
| `install-hooks.sh` + `hooks/pre-commit` + `ci/run-checks.sh` | Activate the lint **and** the secret/PII scan as a git pre-commit hook / CI step once the repo is git-tracked. |
| `hooks/stop-lint.sh` + `.claude/settings.json` Stop hook | **Auto-fires the lint + secret/PII scan at the end of every Claude Code session** in this repo (loop-guarded; blocks "done" on FAIL/finding, silent when clean). Makes both gates automatic. |

**How the layers compose (weakest → strongest enforcement):** the playbooks *explain* → `lint-platform.sh` *certifies on demand* → the **Stop hook** *auto-fires it in Claude Code* → the git pre-commit hook + CI *auto-fire it on commit/push once under git*. Plus `new-skill.sh` makes new work correct **by construction**, and the CLAUDE.md top-of-file router + [operating-model.md](./operating-model.md) route every task (A/B/C/D) to its playbook + gate.

## What is deliberately NOT linted (and why)

- **Voice / banned phrases / house-style rules** — a naive grep false-positives because a brand/style skill lists them as examples. Enforce these at authoring time inside a foundation skill, and behaviourally via `eval-runner.sh`, rather than with a blunt source grep.
- **Anything needing live MCP access** — out of scope for a local pre-commit lint.

If you add a workbench with its own load-bearing invariant (e.g. an autonomy guardrail for a code-writing skill), add a check to `lint-platform.sh` for it and document the *why* in the table above.

## When you change an invariant

1. Edit the check in `lint-platform.sh` first.
2. Run `./lint-platform.sh` — confirm it exits 0 (or only the expected WARNs).
3. Update the table above to explain the new rule's *why*.
4. If the rule propagates across skills, grep the whole `skills/` tree before declaring it live.
